# Поиск аномалий в телеметрии

Пакетный детектор выделяет интервалы необычной работы оборудования по восьми каналам телеметрии. Сравниваются пороговое правило и две конфигурации Isolation Forest. Оценка ведётся по событиям, чтобы серия срабатываний в рамках одного сбоя учитывалась как одна найденная аномалия.

## Данные и разбиение

Использованы 35 CSV Skoltech Anomaly Benchmark. В записи нормальной работы 9 405 измерений. Ещё 34 файла содержат по одному размеченному событию. Данные зафиксированы на коммите `b2c0d46c2971dcbfe71e26087b6d231998bb91c2`. [Исходные данные SKAB](https://github.com/waico/SKAB/tree/b2c0d46c2971dcbfe71e26087b6d231998bb91c2/data)

- **Обучение** — только `anomaly-free/anomaly-free.csv`. Из этой записи получены границы датчиков, обучены модели и вычислены кандидаты порогов.
- **Валидация** — 24 целых эксперимента. На них выбраны пороги, число измерений для подтверждения тревоги и итоговый детектор.
- **Тест** — 10 других экспериментов. Разбиение выполнено внутри категорий `valve1`, `valve2` и `other` с зерном 42. Списки файлов хранятся в [metrics.json](reports/metrics.json), сводка по записям — в [recordings.csv](reports/recordings.csv).

CSV использует разделитель `;`. Загрузчик проверяет обязательные каналы, конечность показаний и строгий порядок временных меток. В исходных данных преобладает шаг в одну секунду. Разрывы больше пяти секунд разделяют последовательности срабатываний и сбрасывают скользящее окно. [График нормальной записи](reports/normal.png)

## Детекторы и тревоги

1. **Пороговое правило.** Измерение подозрительно, если хотя бы один канал выходит за двусторонний квантильный диапазон нормальной записи.
2. **Isolation Forest.** Модель получает текущие показания восьми датчиков. Порог оценки аномальности задан квантилем оценок на нормальной записи.
3. **Isolation Forest со скользящими признаками.** К текущим показаниям добавлены среднее и стандартное отклонение за последние десять измерений, включая текущее. В начале сегмента используются доступные измерения. Вариант добавлен после первого прогона на сырых признаках, чтобы проверить предусмотренную планом гипотезу о пользе истории. Выбор конфигурации по-прежнему опирается на валидацию.

Для всех вариантов проверены пять квантильных порогов и подтверждение после 1, 3 или 5 подряд идущих подозрительных измерений. Критерий выбора — F1 по событиям на валидации. При равенстве выигрывает вариант с меньшим числом лишних тревог. В выбранном детекторе подтверждение занимает пять подозрительных измерений подряд. В выходном CSV сохраняются время первого подозрительного измерения, время подтверждения и время последнего подозрительного измерения.

## Результаты

Каждая серия соседних строк с `anomaly=1` считается одним событием. Оно найдено, если тревога **подтверждена** внутри размеченного интервала. Одна тревога засчитывается каждому событию. Остальные тревоги считаются лишними, включая повторные и слишком ранние. Задержка отсчитывается от начала события до подтверждения тревоги. Поле `changepoint` используется для графика.

| Детектор | F1 на валидации | F1 на тесте | Найдено из 10 | Точность тревог | Лишние тревоги | Лишние в час | Медианная задержка |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Пороговое правило | 0,179 | 0,087 | 1 | 7,69% | 12 | 3,98 | 4 с |
| Isolation Forest | **0,182** | 0,063 | 2 | 3,77% | 51 | 16,92 | 103,5 с |
| Isolation Forest со скользящими признаками | 0,180 | 0,094 | 3 | 5,56% | 51 | 16,92 | 13 с |

На валидации выиграл Isolation Forest на исходных показаниях, поэтому скрипт сохраняет его. На тесте пороговое правило выдало в четыре раза меньше лишних тревог, а вариант со скользящими признаками нашёл больше событий. Разница между вариантами соответствует одному или двум событиям на тесте. У всех трёх вариантов много пропусков, поэтому результаты описывают этот эксперимент на одном стенде. Частота тревог рассчитана на 3,01 часа наблюдений из расчёта одной секунды на строку. Задержка рассчитана только по найденным событиям.

На графиках зелёный фон показывает разметку, оранжевый — подтверждённую тревогу, фиолетовая линия — разбираемый момент. В `other/10.csv` модель обнаружила событие через 180 секунд и выдала 26 лишних тревог. На этот файл пришлось 26 из 51 лишней тревоги на тесте. В `other/1.csv` единственная тревога пришлась за пределы размеченного интервала. ## Запуск

Проверено на Python 3.12. Для примера ниже распакуй архив SKAB так, чтобы файлы оказались в `data/SKAB/data`, либо передай фактический путь в `--data-dir` и `--input`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe train.py --data-dir data/SKAB/data --output-dir artifacts
.\.venv\Scripts\python.exe detect.py --input data/SKAB/data/other/10.csv --model artifacts/detector.joblib --output-dir demo
```

`train.py` сохраняет модель, метрики, графики и сводки. `detect.py` выдаёт `alerts.csv` и `timeline.png`. Для нового CSV достаточно столбца `datetime` и восьми каналов. Если в записи нет тревог, `alerts.csv` содержит заголовки. Используй файл модели, полученный локальным запуском `train.py`.
